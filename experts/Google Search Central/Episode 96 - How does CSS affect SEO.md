# Episode 96: How does CSS affect SEO

Разбор выпуска *Search Off the Record* с Martin Splitt и John Mueller: почему CSS «имеет отношение» к SEO, что не влияет (class names), что ломает смысл (`::before` / `::after` с контентом), CSS-картинки vs `<img>`, и почему screenshot в URL Inspection врёт при `100vh`.

---

## CSS ≠ магия ранжирования, но есть edge cases

Google пишет, что CSS должен быть crawlable — отсюда ощущение «в CSS есть SEO-магия». На практике CSS обычно **норм использовать**, как JS: гибкость иногда приводит к неожиданным провалам для Search / a11y / дебага.

Принцип веба: **контент в HTML, оформление в CSS**. Нарушения этого принципа — главная точка пересечения с SEO.

Web Almanac (CSS 2022): median stylesheet ~68–72 KB (mobile/desktop); находили и чудовища вроде **78 MB** (вероятно data-URL и т.п.). Frameworks дают bloat; unused rules можно вырезать — не все это делают.

---

## Что почти не влияет

| Тема | Вердикт |
| --- | --- |
| Имена CSS-классов / keywords в class | **Не SEO-сигнал.** Можно назвать всё `blurb` — для Google всё равно, для людей ад |
| Keywords в stylesheet | Не нужны |
| `!important` | Про specificity/override стилей, не про SEO |

Class names — атрибуты, не text content. Нормальный parse HTML → текст элементов, атрибуты (включая class) отбрасываются. То же, что выдуманный тег `<keyword>` — не поможет.

---

## `::before` / `::after`: декор ок, контент — нет

Pseudo-elements позволяют вставить «контент» вокруг элемента из CSS (лампочка перед H2 без правки HTML).

| Использование | Ок? |
| --- | --- |
| Декор (иконка, точка, unicode-украшение) | Да — страница без него всё ещё осмысленна |
| Реальный контент / заголовок / `#` у hashtags | **Нет** |

Почему плохо для Search:

- краулеры, боты, часто a11y-инструменты читают **HTML**, не «смысл из CSS»;
- в тесте Martin’а inserted content **не попадает в DOM** → rendering Google его не подхватывает как обычный текст;
- кейс indexing: сайт добавлял `#` через `::before` к «хештегам» → система видела просто слова, без сигнала hashtag.

Ментальная модель: если это важно для смысла/индекса — должно быть в HTML. В выпуске признали дыру в документации Search Central — планировали описать.

## `100vh` hero и screenshot в URL Inspection

`height: 100vh` = 100% высоты viewport.

Google при render делает **viewport expansion** (особенно по высоте), чтобы поймать то, что срабатывает «только in viewport». Элемент на `100vh` растёт вместе с расширением → screenshot превращается в гигантскую картинку «без текста».

| Вопрос | Ответ выпуска |
| --- | --- |
| Значит ли это hidden content? | Скорее нет: текст всё ещё в DOM, доступен |
| Чинить ради SEO? | Не обязательно «ради Google»; смотрите UX/a11y — зачем hero на всю высоту при скролле |
| Что смотреть в инструментах | **Rendered HTML**, не screenshot |

Имеет смысл `max-height` и пересмотреть, нужен ли эффект «на весь экран» именно через `100vh`.

## CSS images vs content images

| Тип картинки | Куда класть |
| --- | --- |
| Чисто декоративная (wallpaper, '90s stars GIF, фон) | CSS `background` — ок |
| Часть смысла («посмотрите на этот пейзаж / дом / график рынка») | `<img>` / `<picture>` в HTML |

Если картинка «видна» как background пустого/текстового блока, пользователь видит изображение, а в DOM **нет** content-image → Image Search и связь «текст ↔ image» слабее.

Stock photos «для украшения»:

- как копии часто уже есть у стока → мало выгоды в Image Search;
- если фото всё же смысловая часть материала — семантически ближе к content → лучше `<img>`.

## Таблицы на CSS

Tabular data в «таблицах» из div+CSS вместо `<table>`:

- хуже для распознавания rows/columns при индексации;
- часто хуже для screen readers;
- иногда так делают ради responsive — trade-off осознанный.

---

## Скрытие текста цветом

Классика «цвет текста = фон» сейчас реже. Чаще `display: none` (элемент в DOM, не показан). Старый cloaking-приём не обсуждали как массовый тренд.

---

## Практический чеклист

1. Контент и смысл — в HTML; CSS — про look.
2. Не пихайте keywords в class names.
3. `::before`/`::after` — только декор; hashtags, заголовки, важный текст — в разметке.
4. Content images — `<img>`/`<picture>`, не background «под видом картинки».
5. Decorative backgrounds — CSS ок.
6. В URL Inspection смотрите rendered HTML; странный screenshot с `100vh` — не паникуйте сразу.
7. Tabular data по возможности — настоящие tables.
8. Держите CSS crawlable (как в гайдах); не раздувайте stylesheet data-URL’ами до мегабайт без нужды.
9. Справка по CSS: web.dev, MDN; по Search — developers.google.com/search (после появления заметки про pseudo-elements).

## Кратко

| Миф / вопрос | Реальность |
| --- | --- |
| Class names = SEO | Нет |
| CSS не влияет ни на что | Влияет, когда туда переносят **контент** или ломают UX/отладку |
| `::before` с текстом проиндексируется | Обычно нет (не в DOM) |
| Все images через CSS «лучше» | Только для декора; content — в HTML |
| Страшный screenshot = страница пустая | Смотрите DOM/rendered HTML |

Одна фраза: CSS бьёт по SEO не «весом файла», а когда вы прячете смысл в стилях вместо HTML.
