# Crawling Challenges: What the 2025 Year-End Report Tells Us

Разбор выпуска *Search Off the Record* с Martin Splitt и Gary Illyes: что показала внутренняя сводка по формам crawl issues за 2025 год — какие URL-пространства чаще всего взрывают краулинг и что с этим делать.

---

## Откуда цифры

У Search Relations есть форма жалоб на crawl issues. После валидации заявки попадают в inbox, команда проверяет, есть ли реальная проблема, и раскладывает кейсы по внутренним bucket’ам. Дальше crawl-quality команда действует в зависимости от категории.

Большинство репортов укладывается в несколько повторяющихся типов. «Other» — самый маленький хвост.

---

## Распределение проблем (2025 wrapped)

| Категория | Доля репортов (порядок) | Суть |
| --- | --- | --- |
| **Faceted navigation** | ~**50%** | Фильтры/сортировки → взрыв комбинаций URL |
| **Action parameters** | ~**25%** | `add_to_cart`, wishlist и т.п. в GET/ссылках |
| **Irrelevant parameters** | ~**10%** | UTM, session ID и «непонятные» параметры |
| **Calendar / event dates** | ~**5%** | Бесконечные даты/календари, часто из плагинов |
| **Other** | ~**2%** | Double encoding и прочий интернет-зоопарк |

Цифры — из обсуждения внутреннего отчёта Gary; это не публичная статистика всего веба, а структура того, что **реально прилетает** в crawl-issue pipeline Google.

---

## 1. Faceted navigation (~половина всех кейсов)

Фильтры магазина (цена, бренд, «мультирозетка с отдельными выключателями» и т.д.) дают комбинаторный взрыв URL.

Почему это бьёт по сайту:

1. Googlebot (и любой крупный краулер) **не знает заранее**, полезно ли URL-пространство.
2. Чтобы решить «краулить / не краулить», нужно обойти **большой кусок** паттернов.
3. Пока идёт разведка — нагрузка может уложить сервер для пользователей.
4. Backoff начинается, когда уже видны сигналы страдания сайта — до этого краулинг идёт агрессивно.

Тяжёлый симптом — падение хостинга. Мягче — аномалии в access logs / honeypot-алерты.

### Что делать

В большинстве случаев faceted URL **не** главный способ находить новый контент для Google. Разумный путь:

- `Disallow` опасных путей/комбинаций в **robots.txt**;
- смотреть примеры правил для search/parameter combinations в документации Google по robots.txt и переносить логику на свои facet-паттерны;
- помнить: robots.txt кэшируется порядка **~24 часов** — эффект не мгновенный.

Проблема усугубляется, если платформа **не даёт** править robots.txt.

## 2. Action parameters (~25%) — сюрприз года

Идея из web security / старых GET-паттернов: действие закодировано в URL.

Типичный современный (и «мягкий») вариант не `DROP TABLE`, а:

- `?add_to_cart=true`
- `?add_to_wishlist=true`
- `update_profile=true` и аналоги

Googlebot **не** ходит по магазину как покупатель. Но если «Add to cart / wishlist» — обычные `<a href>` с параметрами, краулер их извлекает.

Эффект на crawl space:

| Ссылки на странице | Rough эффект |
| --- | --- |
| Базовый product URL | 1× |
| + add to cart | ~2× |
| + wishlist | ещё множитель |
| Комбинации | легко ×3 и выше |

Частый источник — **WordPress / WooCommerce-плагины**. Search Relations в таких случаях предпочитает чинить «в корне»: issue в open-source репозиторий (WooCommerce отреагировал быстро; другой плагин на момент записи висел без владельца), вместо бесконечных внутренних костылей под каждый параметр.

Для владельцев сайта: закрыть паттерны в robots.txt; по возможности убрать state-changing действия из crawlable GET-ссылок (POST/кнопки без индексируемых URL).

## 3. Irrelevant parameters (~10%)

Сюда входят UTM, `jsessionid`, session IDs и т.п.

Google **хорошо** справляется с классическими session/UTM-паттернами — пока вы не изобретаете свой `?s=…`.

Почему короткий `s=` опасен:

- это может быть session, search, service id, sentiment…;
- значение бывает numeric или hex-random;
- без данных краулер не отличит «шум» от «смыслового» параметра → снова нужно много краулить, чтобы понять, меняет ли параметр контент.

Митигация:

- не тащите session ID в URL (они «из 2000-х», краулеру session persistence не нужна);
- `Disallow` явно шумовых параметров в robots.txt;
- не переименовывайте известные параметры в однобуквенные загадки.

В доках Google session ID уже упоминались; проблема не в отсутствии документации, а в том, что паттерн всё ещё жив (3-е место в репортах — Gary этим недоволен).

---

## 4. Calendar / event infinite spaces (~5%)

Страница «на каждый день» + контент, из‑за которого soft 404 не детектится → для краулера пространство выглядит бесконечным.

Худший кейс из отчёта: коммерческий WordPress event-виджет, который вешал calendar infinite space **почти на каждый path** сайта (`/`, `/1`, `/1/2` …). Outreach к разработчику не сработал; open-source фикса нет.

Быстрый рычаг снова — robots.txt disallow на date/event-паттерны, если плагин не чинят.

---

## 5. Other (~2%): double percent-encoding

Классика: один слой URL-encode при рендере, второй — при записи в БД / другим плагином → ссылка double-encoded.

Google percent-decode’ит извлечённый URL один раз, остаётся ещё один слой encoding → краулят «кривые» адреса. Если сайт отвечает ошибкой — системы могут среагировать умнее; если отдаёт **случайный/похожий контент** — bogus URL продолжают казаться «нормальными» для краулинга.

Ловится плохо: часть контента уже double-encoded, часть нет; чинить дороже, чем не допускать encode в двух местах пайплайна.

---

## Практический чеклист по итогам 2025

1. **Facet filters** — не отдавайте краулеру все комбинации; режьте robots.txt / canonical / design URL space до того, как логи загорятся.
2. **Cart / wishlist / «action» в GET** — уберите из crawlable links; проверьте плагины CMS.
3. **Session / UTM / однобуквенные параметры** — стандартизируйте имена; не заставляйте бота угадывать семантику `s=`.
4. **Календари и event-виджеты** — проверьте, не плодят ли они infinite date URLs на каждом path.
5. **Encoding** — encode один раз, в одном слое; следите за повторным encode плагинами.
6. Смотрите **access logs**: аномальный паттерн Googlebot на facet/action — повод решать, полезен ли этот crawl (часто нет).

---

## Кратко

Year-end картина по crawl-issue репортам 2025 простая и жёсткая: почти половина — **facets**, четверть — **action parameters** вроде add-to-cart, дальше session/UTM-шум, календари и хвост double-encoding.

Это не «Googlebot внезапно сломался». Это сайты (часто e-commerce и CMS-плагины) сами открывают огромные или бесполезные URL-пространства, а краулер обязан их разведать, прежде чем понять, что туда ходить не стоит — иногда ценой нагрузки на прод.

Самый быстрый общий рычаг из выпуска: **robots.txt на плохие паттерны** (+ чинить генераторы URL в плагинах/шаблонах, когда можете).
